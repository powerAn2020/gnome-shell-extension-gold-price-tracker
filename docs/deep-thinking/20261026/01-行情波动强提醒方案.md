# 行情波动强提醒方案

## 方案逻辑通俗说明（开篇必读）

- **问题是什么**：
  黄金价格在国际政治、经济突发事件或主力交易时段可能出现短时间剧烈跳水或暴涨，或者单日持续大幅单边运行。用户仅依靠自己定时抬头看顶栏，容易错过关键调仓或止盈止损时机。
- **方案怎么解决它**：
  1. 插件每次通过后台拉取到最新积存金价格后，会将其交给「波动告警引擎」；
  2. 引擎同时计算两个维度的指标：
     - **今日累计涨跌幅（%）**：对比昨日收盘价，绝对值是否超过了用户设定的阈值（例如 ±1.0%）；
     - **短时突发波动（元/克）**：对比上一次拉取的价格，价差绝对值是否超过了设定的单次跳动阈值（例如 2.00 元/g）；
  3. 当满足任一告警条件时，系统会弹出 GNOME 原生的紧急常驻通知（`Urgency.CRITICAL`，不会自动消失，直到用户点击或手动划走），并调用系统的提示声音，确保用户即时感知；
  4. 为避免价格在阈值附近震荡或连续刷新导致桌面通知被刷屏，方案引入了**独立防骚扰冷却时间**（默认 5 分钟），同一维度的告警在冷却期内不会重复触发；并且对于刚启动首笔数据或开盘隔夜跳空（间隔 > 10 分钟）进行跳空防抖，杜绝假报警。
- **为什么这样就能解决**：
  双指标解耦让「单日大趋势」与「短时间黑天鹅突变」各司其职，不会互相干扰覆盖；GNOME 原生 CRITICAL 级通知提供了最高优先级的视觉焦点；冷却机制保证了强提醒的同时不打扰正常工作。

## 二、对抗性审查（红队攻击与防御）

1. **攻击点一：开机冷启动时 `_lastPrice` 为 0 或未定义导致假暴涨。**
   - **防御**：`_lastPrice` 初始化为 `null`，第一次抓取仅做记录锚定，跳过突发计算。
2. **攻击点二：午盘休市到夜盘开市时，由于国际金价已大幅变动，产生跳空，导致单次突变误报。**
   - **防御**：若当前拉取时间与上次成功拉取时间间隔超过 10 分钟（即经历过休市、系统睡眠或网络中断重连），本次自动忽略单次突发波动检测，仅保留今日累计涨跌幅检测。
3. **攻击点三：GNOME 无音频输出设备或静音环境抛出异常中断主轮询。**
   - **防御**：声音播放逻辑使用独立 `try ... catch` 环绕，不影响通知弹窗与后续 UI 渲染。
